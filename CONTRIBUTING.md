# Contributing to SafeTalk

SafeTalk is proprietary software. Contributions are welcome only from people who have received prior written permission from the copyright holder. The project's license does not grant general permission to use, modify, or distribute the software.

## Before you begin

1. Obtain written permission from the copyright holder before accessing or making changes for contribution.
2. Confirm the authorized scope of your contribution and any applicable confidentiality or intellectual-property terms.
3. Follow the setup instructions in the root [README](./README.md).

Do not submit a contribution if you do not have the required permission. A pull request or patch does not itself grant permission to use or distribute this software.

## Contribution workflow

For authorized contributors:

1. Discuss the proposed change and confirm it is within the approved scope.
2. Make a focused change that follows the existing project patterns.
3. Run the relevant checks before submitting:

   ```bash
   cd client
   npm run lint
   npm run build
   ```

4. Submit the change with a clear summary, motivation, and testing notes.
5. Wait for review and approval before treating the contribution as accepted.

Do not include credentials, personal data, generated build output, or unrelated changes in a submission. Do not add dependencies without explaining why they are needed.

## Reporting issues

Only people authorized by the copyright holder should access non-public project materials or submit private reports. Do not include secrets or sensitive user data in an issue or report.
